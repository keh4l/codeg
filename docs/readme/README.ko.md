<summary><strong>창마다 자체 탭</strong> 자세히</summary>
<br/>

- 설정 → 일반의 '창 간 대화 탭 동기화'로 바꿀 수 있으며 기본으로 켜져 있습니다. 켜져 있으면 같은 서버에 연결된 모든 창과 기기(PC, 태블릿, 휴대폰)가 공식 빌드처럼 하나의 탭 세트를 공유합니다.
- 끄면 한 창에서 대화 탭을 열거나 전환하거나 닫아도 다른 창은 그대로이고, 새로고침하면 그 창의 탭이 그대로 돌아옵니다.
- 대화, 메시지, 삭제는 이 설정과 관계없이 항상 모든 창에 반영됩니다.
- 이 설정은 서버에 저장됩니다. 어느 창이나 기기에서 바꾸든 그 서버에 연결된 모든 창과 기기가 함께 바뀝니다. (0.35.2-1 이하에서는 브라우저마다 따로 저장되었고 브라우저에서는 기본으로 꺼져 있었습니다.)
- 업스트림 요청: [spacering-net/codeg#547](https://github.com/spacering-net/codeg/issues/547).

<details>
<summary><strong>답변과 메시지 번역</strong> 자세히</summary>
<br/>

- 설정 → 번역에 [Alibaba Cloud Bailian](https://bailian.console.aliyun.com/) 또는 [Tencent Cloud TokenHub](https://console.cloud.tencent.com/tokenhub/apikey)의 API 키를 넣으면 켜집니다. 요금은 각 플랫폼 기준을 따릅니다. 기본값은 Bailian의 `qwen-mt-flash`이며, 테스트에서 단락당 약 0.5초였습니다.
- 답변: "답변 번역" 스위치를 켜면 에이전트가 답변을 한 덩어리씩 다 쓸 때마다(도구 호출이나 생각으로 넘어가거나 턴이 끝날 때) 그 덩어리 전체를 한 번의 요청으로 번역해(모델이 덩어리 전체를 맥락으로 봅니다) 원문 대신 번역문을 보여 주며, 쓰는 동안에는 원문을 보여 줍니다. 각 답변 아래의 번역 버튼으로 원문으로 돌아갈 수 있고, 자동 번역이 꺼져 있을 때는 그 답변만 번역할 수 있습니다. 생각 과정은 펼칠 때 본문을 번역하며(접혀 있을 때도 보이는 한 줄 제목은 원문 그대로) 같은 버튼으로 전환됩니다. 코드 블록과 도구 호출은 번역하지 않습니다. 복사 버튼은 화면에 보이는 내용을 복사합니다.
- 세션 이름: 답변 자동 번역이 켜져 있으면 에이전트가 붙인 세션 이름도 사이드바, 탭, 대화 제목 표시줄에 사용자의 언어로 표시합니다. 직접 지은 이름은 번역하지 않으며, 사이드바의 세션에 마우스를 올리면 원래 이름을 볼 수 있습니다.
- 질문 카드: 에이전트가 질문하면 질문과 선택지를 기본으로 번역해 보여 줍니다(설정 → 번역에서 끌 수 있습니다). 카드 오른쪽 위 버튼으로 원문과 번역을 전환하며, 답변은 에이전트가 제시한 원래 선택지로 보냅니다. "기타"에 쓴 답변은 옆의 번역 버튼이나 `⌘⇧L`로 대상 언어로 번역하고, 다시 누르면 되돌립니다. "보낼 때 번역"이 켜져 있으면 제출 전에 자동으로 번역합니다. 비밀로 표시된 질문은 번역에 보내지 않습니다.
- 할 일 목록: 에이전트가 세운 할 일 목록(답변 안의 '계획 업데이트' 줄, 대화 위의 떠 있는 계획, 세션 상세의 계획)은 각 단계를 기본으로 번역해 보여 주며, 목록 전체를 한 번의 요청으로 번역합니다(설정 → 번역의 "할 일 목록 자동 번역"으로 끌 수 있습니다). 계획 줄을 펼치면 목록 아래에 나오는 버튼(떠 있는 계획은 제목 줄)으로 원문과 번역을 전환하고, 자동 번역이 꺼져 있으면 이 버튼으로 직접 번역합니다.
- 메시지: 입력창의 번역 버튼, `⌘⇧L`(Windows와 Linux에서는 `Ctrl+Shift+L`) 또는 오른쪽 클릭 메뉴로 입력창의 내용을 그 자리에서 대상 언어(기본값 영어)로 번역합니다. 멘션, 슬래시 명령, 경로, 코드는 그대로 남고, `⌘Z` 한 번으로 원문으로 돌아갑니다. 번역은 누를 때만 하며, 쓰다 만 초안이 전송되는 일은 없습니다. "보낼 때 번역"을 켤 수도 있습니다. 보낸 뒤에는 메시지 옆 번역 버튼으로 번역 전에 쓴 원문으로 돌아갈 수 있고, 복사도 보이는 내용을 따릅니다.
- 요청 한도에 걸리면 `qwen-mt-lite`나 다른 엔진으로 넘어갑니다. 용어집으로 특정 용어의 번역을 고정할 수 있으며, 번역을 비워 두면 그 용어는 원문 그대로 둡니다.
- API 키는 OS 키체인(서버판은 데이터 디렉터리의 `tokens.json`)에 저장되며 데이터베이스에는 기록되지 않습니다. 저장한 키는 설정 화면의 눈 모양 버튼으로 볼 수 있습니다. 번역 요청은 프록시를 거치지 않고 직접 연결하며, 프록시로만 밖에 나갈 수 있는 네트워크에서는 자동으로 프록시를 씁니다.
- 답변의 번역문은 표시용일 뿐이며, 대화 기록에는 에이전트의 원문이 그대로 남습니다. 메시지의 번역 전 원문은 로컬 데이터베이스에 따로 저장되며, 번역 캐시를 비워도 지워지지 않습니다.

- 공식 빌드에서는 응답을 선택했을 때의 「텍스트 복사 / 인용 / 질문」 말풍선이 선택 영역 옆에 붙고, 휴대폰의 메뉴도 선택 영역 옆에 붙습니다. 위에 둘지 아래에 둘지는 휴대폰이 정하고 웹 페이지는 그 위치를 읽지도 옮기지도 못해서, 둘이 자주 겹쳤습니다. 이 빌드에서는 손가락으로 선택하면 이 버튼들과 선택한 글자 수가 입력창 아래에 나오고, 선택이 풀릴 때까지 폴더와 브랜치 줄을 대신합니다. 휴대폰의 메뉴는 입력창을 넘어 여기까지 오지 않습니다. 「질문」은 그 줄에서 바로 질문을 입력합니다. 마우스로 선택하면 예전처럼 선택 영역 위에 말풍선이 뜹니다.
- 입력창 메뉴의 빠른 메시지는 입력창 왼쪽 아래의 「+」에도 있습니다. 보낼 메시지 번역에는 전용 버튼이 있습니다.
- iOS에서는 웹 페이지의 일반 텍스트에 대한 시스템 메뉴에 원래 「전체 선택」이 없습니다(입력창에만 있음). 응답 전체를 복사하려면 응답 아래의 복사 버튼을 쓰세요.

<summary><strong>웹에서 서버 다시 시작</strong> 자세히</summary>
<br/>

- 공식 빌드를 서버에 배포하면 웹 페이지에서 codeg를 다시 시작할 방법이 없습니다. 다시 시작해야 적용되는 설정(외관, 언어, 공급자 목록, 브라우저 프록시 등)을 바꿨거나 서비스에 문제가 생기면 서버에 로그인해 다시 시작해야 합니다. 서버에서 백업을 복원할 때도 마찬가지입니다. 복원은 다시 시작한 뒤 적용되는데, 호출하는 다시 시작이 「설치 대기 중인 업데이트」만 받아들여서 매번 「서비스를 다시 시작하지 못했습니다. 직접 다시 시작하세요」로 끝납니다.
- 이 빌드는 「설정 → 시스템」의 「소프트웨어 업데이트」 아래에 「codeg 다시 시작」을 추가했습니다. 「다시 시작」을 누르면 먼저 확인을 받고, 실행 중이라 중단될 대화 수도 보여 줍니다. 확인하면 카운트다운한 뒤 서비스가 돌아오기를 기다렸다가 페이지를 새로 고칩니다. 열려 있는 다른 창의 상태 표시줄에도 「다시 시작하는 중」이 표시됩니다.
- 다시 시작하는 방식은 제자리 업데이트와 같습니다. Docker나 수퍼바이저(`--supervise`) 아래에서 실행 중이면 `CODEG_RESTART_DELAY_MS` 뒤에 수퍼바이저가 다시 실행하고, 단독으로 실행 중이면 프로세스가 그 자리에서 다시 시작합니다(systemd 등에는 같은 프로세스로 보입니다). 일반 다시 시작은 업데이트의 시험 실행 기간에 들어가지 않고 자동 롤백도 일으키지 않습니다. 업데이트를 다운로드하거나 설치하는 중에는 다시 시작할 수 없습니다.
- 서버에서 백업을 복원한 뒤 결과 패널의 「지금 재시작」도 같은 다시 시작을 써서, 복원이 자동으로 적용됩니다.
- 서버 빌드에서만 표시됩니다. 데스크톱 앱이나 데스크톱의 내장 웹 서비스에 브라우저로 연결했을 때는 표시되지 않으며, Windows 서버는 제자리 업데이트와 마찬가지로 아직 지원하지 않습니다.

<summary><strong>하위 에이전트가 오류로 멈춰도 이어서</strong> 자세히</summary>
<br/>

- 메시지에서 에이전트를 @ 하면 메인 에이전트가 `delegate_to_agent`로 작업을 넘기고, 그 에이전트는 자기 하위 세션에서 작업합니다. 공식 빌드의 `resume_delegation`은 취소되었거나 크래시로 중단된 하위 작업만 되살릴 수 있습니다. 하위 에이전트의 턴이 오류로 끝난 경우(네트워크 끊김, 사용 한도나 속도 제한, 로그인 만료, 제공자의 요청 거부, 토큰 예산 소진 등)는 '실패'로 기록되어, 메인 에이전트는 새 하위 세션에서 처음부터 다시 할 수밖에 없고 하던 작업의 맥락은 사라집니다.
- 이 빌드는 이런 실패도 중단으로 봅니다. 하위 작업의 결과에 세션과 하던 작업이 남아 있으며 원인이 해결되면 `resume_delegation`으로 이어서 할 수 있다고 적힙니다. 메인 에이전트는 이를 보고 원래 하위 세션에서 계속하며, task_id는 그대로이고 대화 속 원래 하위 에이전트 카드에도 진행 상황이 계속 표시됩니다.
- 사용법: 네트워크가 돌아오거나 한도를 충전하거나 다시 로그인한 뒤, 메인 에이전트에게 '이어서 하게 해 줘'라고 말하면 됩니다.
- 세션이 만들어지기 전에 실패한 경우(에이전트가 시작되지 못한 경우 등)는 이어서 할 것이 없으니 다시 위임해야 합니다. 끝난 하위 작업에 새 요청을 덧붙이려면 `continue_delegation`을 씁니다(‘하위 에이전트가 자기 worktree에서 작업’ 참고).

</details>

<summary><strong>에이전트가 @ 어시스턴트를 만들어 줌</strong> 자세히</summary>
<br/>

- 공식 빌드의 @ 어시스턴트(메시지에서 @ 할 수 있는 위임 프리셋: 에이전트, 그 모든 옵션, 상시 지침)는 ‘설정 → 협업 → 다중 에이전트 협업 → 어시스턴트’에서 한 항목씩 채우는 수밖에 없고, 에이전트가 도와줄 수 없습니다.
- 이 빌드는 에이전트에 `create_assistant`와 `update_assistant` 두 도구를 추가했습니다. 대화에서 원하는 어시스턴트를 말하면(예: “리뷰어를 추가해 줘. Codex, GPT-5.5, 추론 high, 읽기 전용, diff 리뷰용”) 에이전트가 만들고, “리뷰어를 GPT-5.4로 바꿔 줘”, “리뷰어 지침에 규칙 하나 추가해 줘”라고 하면 수정합니다.
- 만들 때 Codeg가 그 에이전트를 잠깐 실행해 실제 옵션을 읽습니다(몇 초 걸림). 지정한 옵션은 말한 대로, 나머지는 그 에이전트 자체의 기본값(편집기에서 ‘추천’으로 표시되는 값)을 씁니다. 수정할 때 지정하지 않은 옵션은 그대로 둡니다. 모델이나 옵션이 맞지 않으면 저장하지 않고, 고를 수 있는 값을 에이전트에 알려 줍니다.
- 대화에는 ‘어시스턴트 … 생성 중’ 줄이 나타나고, 펼치면 어시스턴트의 에이전트, 옵션, 상시 지침을 볼 수 있으며 ‘편집’을 누르면 설정과 같은 편집기가 열립니다. 만든 어시스턴트는 바로 @ 메뉴에 나타나고 바로 위임할 수 있습니다.
- 스위치는 ‘설정 → 협업 → 대화 내 도구’의 ‘어시스턴트 만들기’이며 기본값은 켜짐입니다. 끄면 에이전트에게 두 도구가 보이지 않습니다. 파일과 명령을 직접 처리하도록 설정한 에이전트는 위임 도구와 마찬가지로 이 도구를 받지 않습니다.

</details>

<summary><strong>하위 에이전트가 끝나면 메인 에이전트를 깨움</strong> 자세히</summary>
<br/>

- 공식 빌드에서는 메인 에이전트가 하위 에이전트를 보낸 뒤 `get_delegation_status`로 직접 확인하는 수밖에 없습니다. 끝날 때까지 붙잡혀 기다리거나, 틈틈이 확인하거나 둘 중 하나입니다. 일단 턴을 끝내면 하위 에이전트가 끝나도 아무도 알려 주지 않아, 다시 메시지를 보내 확인하라고 일러 줄 때까지 그대로입니다.
- 이 빌드는 하위 에이전트가 끝나면(또는 도중에 오류로 멈추면) 결과를 메인 에이전트에게 돌려보냅니다.
  - 메인 에이전트가 쉬는 중: 2초 기다렸다가(동시에 끝난 것은 하나로 묶음) 자동으로 턴을 시작하고, 메인 에이전트는 결과를 보고 이어서 합니다.
  - 메인 에이전트가 턴을 진행 중: Claude Code, Codex, Grok, Kiro, Antigravity는 그 턴에 바로 끼워 넣고, 다른 에이전트는 그 턴이 끝난 뒤 자동으로 새 턴을 시작합니다.
  - 마침 메시지를 보내는 중: 결과를 메시지와 함께 넘깁니다.
- 대화에는 ‘하위 작업 결과를 돌려줌’ 줄이 나타나 어느 하위 에이전트인지, 완료인지 실패인지, 얼마나 걸렸는지 보여 줍니다. 펼치면 각 결과의 요약과 ‘세션 열기’가 있습니다. 메시지와 함께 넘긴 것은 메시지 아래에 ‘하위 작업 결과 N개 첨부’로 표시됩니다. 이 줄은 codeg가 메인 에이전트에게 보낸 것이어서, 사용자가 한 말처럼 채팅 채널로 전달되지 않고 세션 제목을 짓는 데도 쓰이지 않습니다.
- 메인 에이전트가 이미 `get_delegation_status`나 `cancel_delegation`으로 직접 받은 결과는 다시 보내지 않습니다. 메인 에이전트나 사용자가 직접 취소한 하위 작업은 보내지 않습니다.
- 중지를 누르면 메인 에이전트와 그 아래에서 돌고 있는 하위 에이전트가 함께 멈춥니다. 공식 빌드와 같습니다. 그 전에 끝났지만 아직 전달되지 않은 결과는 다음 메시지와 함께 넘깁니다. 메인 에이전트의 턴이 오류로 끝나면(속도 제한, 네트워크 끊김 등) 공식 빌드는 하위 에이전트도 함께 취소하지만, 이 빌드는 끝까지 하게 둡니다. 이런 경우와 자동 계속이 20번 연달아 이어진 뒤에는 새 턴을 자동으로 시작하지 않고, 결과는 다음 메시지를 기다렸다가 함께 넘기며, ‘N개 실행 중’ 옆에 그렇게 표시됩니다.
- 스위치는 ‘설정 → 협업 → 다중 에이전트 협업 → 일반’의 ‘하위 에이전트가 끝나면 메인 에이전트 깨우기’이며 기본값은 켜짐이고, 그 뒤에 시작한 세션부터 적용됩니다. 끄면 공식 빌드처럼 메인 에이전트가 직접 확인해야 합니다.

<details>
<summary><strong>하위 에이전트가 자기 worktree에서 작업</strong> 자세히</summary>
<br/>

- 공식 빌드의 하위 에이전트는 모두 메인 에이전트의 작업 디렉터리에서 일하므로, 코드를 고치는 하위 에이전트 둘을 동시에 보내면 같은 파일을 고치게 됩니다. 어떤 모델을 쓸지는 @ 어시스턴트나 설정에서 미리 정해 두는 수밖에 없어 메인 에이전트가 작업에 맞게 고를 수 없습니다. 하위 에이전트가 끝난 뒤 조금 더 고치려면 새 세션을 열어 처음부터 다시 설명해야 합니다.
- 이 빌드는 `delegate_to_agent`에 매개변수 세 개를 추가했습니다.
  - `isolation: "worktree"`: 하위 에이전트가 새로 만든 git worktree에서 일합니다. 브랜치는 `delegate/<번호>`이고, 메인 에이전트가 지금 있는 커밋에서 만듭니다. 메인 에이전트가 아직 커밋하지 않은 변경은 들어 있지 않으며, 위임 응답에서 이를 알려 줍니다. worktree는 ‘할 일’에 설정한 ‘워크트리 위치’(설정하지 않았으면 저장소 옆)에 두고, 디렉터리 이름은 `<저장소 이름>-delegate-<번호>`입니다. 하위 에이전트가 끝나면 결과에 경로, 브랜치, 바꾼 내용이 적히고, 메인 에이전트가 검토한 뒤 git으로 병합하거나 사용자에게 맡깁니다. 커밋이 한 번 이상 있는 git 저장소에서만 쓸 수 있습니다.
  - `model`과 `config`: 이번 위임에만 적용되는 모델과 옵션(예: `{"reasoning_effort": "high"}`)으로, @ 어시스턴트나 설정의 기본값 위에 얹히며 지정하지 않은 옵션은 그대로입니다. 하위 에이전트가 시작되면 실제로 제공하는 옵션과 대조해, 맞지 않으면 작업을 시작하지 못하게 하고 고를 수 있는 값을 메인 에이전트에 알려 줍니다. 아예 없는 옵션은 무시하고 응답에 그렇게 밝힙니다.
- 새 도구 `continue_delegation`: 이미 끝난(완료, 실패, 취소) 하위 작업에 새 요청을 덧붙여 원래 하위 세션에서 이어서 하게 합니다. 이전 맥락, 작업 디렉터리, 모델, 옵션을 그대로 쓰고, 결과도 똑같이 메인 에이전트에게 돌아갑니다. 덧붙일 때마다 새 라운드가 되고 새 task_id가 붙습니다. `resume_delegation`과의 역할 분담은, 도중에 중단된 것을 이어서 할 때는 resume, 끝난 뒤 더 고칠 때는 continue입니다.
- 위임 줄의 제목 뒤에 모델, 브랜치, ‘N라운드’ 태그가 붙습니다. 펼치면 모델, 옵션, worktree 상태(어느 커밋에서 만들었는지, 파일 몇 개가 바뀌었는지)를 볼 수 있고, ‘열기’를 누르면 작업 공간에서 그 worktree를 열며(변경 확인, 커밋, 병합은 거기서 합니다), ‘워크트리 삭제’를 누르면 삭제합니다. 브랜치까지 함께 삭제할 수도 있습니다.
- worktree는 자동으로 삭제되지 않습니다. worktree를 쓴 하위 세션을 삭제할 때 확인 창에 ‘워크트리도 삭제’ 항목이 추가됩니다. 안에 커밋하지 않은 변경이 있으면 기본으로 체크가 해제되고 몇 곳인지 적힙니다.

</details>

<summary><strong>언제든 끼어들기</strong> 자세히</summary>
<br/>

- 공식판에서는 에이전트가 답하는 중에 Enter를 누르면 대기열에 들어갑니다. 끼어들기는 보내기 버튼 옆 작은 화살표 안에 있고, 턴에 바로 들어가는 건 Claude Code와 Codex뿐입니다. 다른 에이전트는 설정에서 '실시간 피드백'을 켜도 에이전트가 직접 확인할 때 읽는 메모가 될 뿐입니다. 대기열은 현재 브라우저에만 있어 새로고침하면 사라지고, 중지하면 다음 대기 메시지가 바로 나갑니다.
- 이 빌드는 T3 Code를 따릅니다:
  - 보내기 버튼: 입력창이 비어 있으면 중지, 내용이 있으면 아이콘이 클릭 시 동작을 보여 줍니다(끼어들기 ↱ / 대기열 목록+). ⌘/Ctrl을 누르고 있으면 아이콘이 바뀌고, ⌘/Ctrl+클릭은 다른 쪽으로 동작합니다. 휴대폰에서는 보내기 버튼을 길게 눌러 그 메시지만 다른 쪽을 고릅니다.
  - 기본은 끼어들기이며, '설정 → 일반 → 탭과 입력'의 '에이전트가 답하는 중에 보낼 때'에서 대기열로 바꿀 수 있습니다(이 기기에만 적용).
  - 단축키('설정 → 단축키'에서 변경 가능): Enter는 기본 방식, ⌘/Ctrl+Enter는 다른 방식, ⌘/Ctrl+Shift+Enter는 가장 오래된 대기 메시지를 끼워 넣고, 커서가 입력창 맨 앞에 있을 때 Alt+↑는 가장 최근 대기 메시지를 편집합니다.
  - 슬래시 명령은 항상 대기열로 가고, 에이전트가 컨텍스트를 압축하는 동안의 끼어들기도 대기열로 갑니다.
- 끼어들기가 전달되는 방식: Claude Code, Codex, Grok, Kiro(텍스트만), Antigravity 1.5.0 이상은 진행 중인 턴에 넣고 지금 단계가 끝나면 읽습니다. 그 밖의 에이전트는 턴을 멈추고 같은 세션에서 메시지와 함께 다시 시작합니다. 중단된 답변은 '끼어들기로 중단된 시도'로 접히고 진행 중이던 단계는 사라지지만, 위임한 하위 에이전트는 멈추지 않습니다. 네이티브 끼어들기가 없는 Grok은 대기열만 씁니다(취소하면 실행 중인 도구도 멈추기 때문).
- 끼어든 메시지 아래에는 '끼어들기', 전달 중에는 '끼어들기 · 읽기 대기 중'이 표시되며, 다시 불러와도 남습니다.
- 대기열은 서버에 저장되어 모든 창과 기기에서 같은 것이 보이고, 새로고침이나 재시작 후에도 남습니다. 컴퓨터에서는 대화 끝의 점선 말풍선으로, 휴대폰에서는 입력창 위에 표시되며, 각 메시지를 지금 보내기(진행 중인 턴이 있으면 그 턴에, 없으면 새 턴으로), 편집, 삭제, 끌어서 순서 변경할 수 있습니다. 턴이 정상적으로 끝나면 서버가 다음 메시지를 보내며, 브라우저를 모두 닫아도 보냅니다. 아직 전달되지 않은 하위 작업 결과도 함께 갑니다.
- 중지, 오류로 끝난 턴(속도 제한, 네트워크 등), 서버 재시작 뒤에는 대기열이 일시 중지되고 입력창 위에 '대기열 일시 중지됨'과 '계속'이 나타납니다. '계속', 빈 입력창에서 Enter, 새 메시지 중 무엇이든 다시 보내기 시작합니다. 중지할 때 전달되지 않은 끼어들기가 있으면 알려 주고 입력창에 되돌릴 수 있습니다.
- 공식판의 '실시간 피드백'(메모)은 없앴습니다. 설정에 스위치가 없고, 에이전트에 `check_user_feedback` 도구도 주지 않습니다.

## 설치

### 데스크톱

[Releases](https://github.com/keh4l/codeg/releases/latest)에서 최신 설치 파일을 받으세요:

| 운영체제 | 설치 파일 |
| --- | --- |
| macOS(Apple 실리콘 또는 Intel) | `.dmg` |
| Windows(x64 또는 ARM64) | `-setup.exe` |
| Linux | `.deb`, `.rpm`, `.AppImage` |

공식 Codeg와 같은 앱으로 설치되어 공식 앱을 대체하며, 대화와 설정은 그대로 유지됩니다.

> [!NOTE]
> macOS에서 처음 실행할 때 '손상되었습니다' 또는 '열 수 없습니다'라고 나오면 다음 명령을 한 번 실행하거나, 시스템 설정 → 개인정보 보호 및 보안에서 열기를 허용하세요:
>
> ```bash
> xattr -cr /Applications/codeg.app
> ```

### 서버

Linux 또는 macOS:

```bash
curl -fsSL https://raw.githubusercontent.com/keh4l/codeg/keh4l/install.sh | bash
CODEG_STATIC_DIR=/usr/local/share/codeg/web codeg-server
```

Windows(PowerShell):

```powershell
irm https://raw.githubusercontent.com/keh4l/codeg/keh4l/install.ps1 | iex
$env:CODEG_STATIC_DIR="$env:LOCALAPPDATA\codeg\web"; codeg-server
```

둘 다 이 저장소의 릴리스에서 설치되며, 서버에 내장된 업데이트도 여기를 사용합니다.
