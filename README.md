<details>
<summary><strong>每个窗口一套标签</strong> 的细节</summary>
<br/>

- 开关是「设置 → 常规」里的「跨窗口同步会话标签」，默认开启：连到同一个服务的所有窗口和设备（电脑、平板、手机）共用一套打开的标签，和官方版一样。
- 关闭后，在一个窗口里打开、切换或关闭会话标签，其他窗口保持原样；刷新后恢复的是本窗口自己的标签。
- 会话、消息和删除操作不受开关影响，始终同步到所有窗口。
- 开关保存在服务端：在任意一个窗口或设备上切换，连到这个服务的所有窗口和设备会一起切换。（0.35.2-1 及以前按浏览器分别保存，浏览器端默认关闭。）
- 上游的对应需求：[spacering-net/codeg#547](https://github.com/spacering-net/codeg/issues/547)。

</details>

<details>
<summary><strong>翻译回复和消息</strong> 的细节</summary>
<br/>

- 在「设置 → 翻译」里填入[阿里云百炼](https://bailian.console.aliyun.com/)或[腾讯云 TokenHub](https://console.cloud.tencent.com/tokenhub/apikey)的 API Key 后启用，费用按各平台的规则计。默认用百炼的 `qwen-mt-flash`，实测一段约 0.5 秒。
- 回复：打开「回复翻译」开关后，智能体每写完一段（接着去调用工具、思考，或整轮结束）就把这一段整段翻译（同一次请求，模型能看到整段的上下文），用译文替换原文显示；写的过程中先显示原文。每条回复下方的翻译按钮可以切回原文；没开自动翻译时，也可以用它手动翻译这一条。思考过程在展开时翻译正文（折叠时也显示的那行标题保持原文），跟着同一个按钮切换；代码块和工具调用不翻译。复制按钮复制的是当前显示的内容。
- 会话名：开着自动翻译回复时，智能体起的会话名在侧边栏、标签页和会话标题栏里也显示成你的语言；你手动改过的名字不翻译，悬停在侧边栏的会话上能看到原名。
- 提问卡片：智能体向你提问时，问题和选项默认直接显示译文（「设置 → 翻译」里可以关掉），卡片右上角的按钮切换原文和译文；提交的仍是智能体给出的原选项。在「其他」里写的回答，用旁边的翻译按钮或 `⌘⇧L` 翻译成目标语言，再点一次恢复；开着「发送时自动翻译」时提交前自动翻译。标为保密的提问不会送去翻译。
- 待办任务：智能体列出的待办任务（回复里「更新了计划」那一行、对话上方的浮动计划和会话详情里的计划）每一步默认直接显示译文，整张清单一次请求（「设置 → 翻译」里的「自动翻译待办任务」可以关掉）。展开计划那一行后清单下方的按钮（浮动计划在标题栏）切换原文和译文；关掉自动翻译时，用这个按钮手动翻译。
- 消息：用输入框的翻译按钮、`⌘⇧L`（Windows 和 Linux 上是 `Ctrl+Shift+L`）或右键菜单，把输入框里的内容原地翻译成目标语言（默认英语）。@提及、斜杠命令、路径和代码保持原样，`⌘Z` 一步回到原文。只在你按下时才翻译，写到一半的草稿不会发出去。也可以打开「发送时自动翻译」。发出去之后，消息旁的翻译按钮可以切回你翻译前写的原文，复制也跟着显示的内容走。
- 遇到限流时自动换用 `qwen-mt-lite` 或另一个引擎；术语表可以固定专有名词的译法，译文留空表示保持原文不翻。
- API Key 存在系统钥匙串里（服务器版存在数据目录的 `tokens.json`），不写进数据库；保存后在设置页点眼睛按钮可以查看。翻译请求直连，不走代理；网络只能经代理出去时自动改走代理。
- 回复的译文只用于显示，会话记录里保存的仍是智能体的原文。消息翻译前的原文另存在本机数据库里，清空翻译缓存不会删掉它。

</details>

<details>
<summary><strong>查看 Claude Code 子智能体的会话</strong> 的细节</summary>
<br/>

- Claude Code 把每个子智能体（Agent / Task 工具）的整段对话单独存在 `~/.claude/projects/<项目>/<会话 id>/subagents/agent-<id>.jsonl`。官方版的子智能体那一行只能看到它过程的摘要和最终结果（在后台跑的连过程摘要也没有），这份记录打不开。
- 定制版在子智能体那一行加了「查看会话 ↗」，在右侧抽屉里打开这份记录：它收到的任务、思考、回复，以及每次工具调用的输入和输出。和 Codex、Grok 子智能体那一行的是同一个入口。
- 子智能体一启动入口就出现，前台、后台运行都一样；它还在跑时打开，内容每 2 秒刷新一次，正在执行的工具调用显示为运行中。重新载入对话后再打开的是当时的内容，关掉再开就是最新的。
- 以前的对话也能看，只要记录文件还在。

</details>

<details>
<summary><strong>手机上快速切换打开的会话</strong> 的细节</summary>
<br/>

- 屏幕宽度不到 768 像素时（手机，或很窄的浏览器窗口），官方版不显示会话标签栏。要切到别的打开的会话，只能在侧边栏的全部历史里找；已完成的会话侧边栏默认不显示，开着也找不到。
- 定制版把会话标题变成按钮：标题后面是 ⌄ 和打开的数量；别的会话在等你授权或回答时，数量上亮一个橙点。点开后从底部弹出「已打开的会话」，按标签顺序列出全部打开的会话，每个标着状态（需要处理、进行中、待复查、已完成、已取消、未发送）。点一下切过去，点 × 关掉；也能新建会话，或点「全部会话（含历史）」打开侧边栏。点空白处、往下拖或用返回手势关闭。
- 「需要处理」要这台设备连着那个会话才知道：在这台设备上打开过的会话才会显示，没打开过的显示它保存的状态。
- 开着「跨窗口同步会话标签」（默认开启）时，在手机上关掉的会话，电脑上也会关掉，和在电脑上关标签一样。
- 宽度 768 像素及以上（电脑、平板）不变，仍是标签栏。
- 从侧边栏点开的会话先是预览（和电脑上一样），下一个点开的会替换它；它在这里的标题是斜体，点旁边的 📌 就保留下来。也可以像电脑上那样双击侧边栏里的会话直接保留：手机上侧边栏会在点完后稍等一下再收起，好让第二下落在同一行上。
- 对应的需求：[keh4l/codeg#10](https://github.com/keh4l/codeg/issues/10)、[#12](https://github.com/keh4l/codeg/issues/12)。

</details>

<details>
<summary><strong>智能体生成图片</strong> 的细节</summary>
<br/>

- 在「设置 → 图片生成」里添加服务：接口类型选「OpenAI 接口」（OpenAI 官方、Grok 和大多数中转站）或「Gemini 接口」（Google 官方或中转站），地址留空就是官方地址，再填 Key 和模型名，如 `gpt-image-2`、`grok-imagine-image-2.0`、`gemini-3-pro-image`。可以加多个服务。「测试」会生成一张低质量小图确认能用，由服务方计费。
- 打开页面顶部的开关（和「设置 → 协作 → 会话内工具」里的「生成图片」是同一个，默认关闭），并且至少有一个服务填了 Key 和模型后，之后启动的智能体会多出 `image_generate` 和 `image_get_result` 两个工具。智能体可以选模型、宽高比、分辨率和透明背景，也可以传参考图来修改已有的图片；没选模型时用设置里的默认模型。
- 保存位置由智能体传参决定，相对路径按会话的工作目录算；没传时存到 `~/.codeg/generated-images/<日期>/`，这个目录可以在设置里改。
- 对话里每张图一张卡片：生成中显示已用的秒数，完成后显示图片、保存路径（点一下打开）、服务和模型、尺寸和用时。图从文件读，重新载入对话后只要文件还在就能看到。
- 默认附一张约 512 像素宽的预览图给智能体，让它看到结果再决定要不要改，会占用它的一些上下文；智能体用的模型看不了图片时可以在设置里关掉。
- 生成一张图常要几十秒到两分钟。超过这个智能体一次工具调用能等的时间时，先返回任务号，智能体用 `image_get_result` 接着取，见下一节。
- 调接口的是 codeg 自己，智能体只拿到图片文件。API Key 存在系统钥匙串里（服务器版存在数据目录的 `tokens.json`），不写进数据库，也不随配置同步。

</details>

<details>
<summary><strong>短超时的智能体也能等到结果</strong> 的细节</summary>
<br/>

- 智能体对一次 MCP 工具调用能等多久各不相同：ZCode 30 秒；Cursor、Kimi 60 秒；Codex 5 分钟；Claude Code、OpenCode、Qoder、CodeBuddy、Grok、DeepSeek 0.12 起基本不限。官方版里，`get_delegation_status`（等委托任务的结果）可以一次等很久，`ask_user_question`（向你提问）一直等到你回答，超过时限后智能体就当作调用失败接着往下做，提问也就当成没回答。
- 定制版按智能体给这些工具设一个比时限短的上限，例如 ZCode 20 秒、Cursor 45 秒、Codex 4 分钟；不限时的智能体不设上限，和官方版一样。到了上限还没有结果就先返回，告诉智能体下一次怎么接着等。
- 提问：到时你还没回答，问题卡片照样留着，智能体用新工具 `get_question_answer` 接着等；你回答后，答案显示在原来的提问卡片里。
- 「N 个运行中」里每个子智能体后面有「停止」，两个以上时标题行有「全部停止」：你在这里停掉的子智能体，结果不会再送回主智能体。
- 委托任务：`get_delegation_status` 一次最多等到上限，再返回任务当前的状态。开着「子智能体完成后叫醒主智能体」时，主智能体一般不用再等，结果会自己送回来，见「子智能体做完会叫醒主智能体」。生成图片同理，见上一节。
- 等待时每 10 秒向智能体报一次进度，CommandCode 这类按进度续时的智能体能等得更久。

</details>

<details>
<summary><strong>只列你在用的智能体</strong> 的细节</summary>
<br/>

- 内置智能体有 20 个，官方版不管装没装默认全部启用：设置页一长串，新会话的选择器里也挤满还没装的（会话页不会替你安装，选了也用不了），每次打开设置页还要逐个预检。
- 定制版的「设置 → 智能体」只列「我的智能体」，照样可以拖动排序。标题栏的「添加」和列表下方那一行打开「添加智能体」：按名称或描述搜索，按已安装 / 未安装筛选，本机已安装的排在前面，一次多选。没安装的，加进来后在详情里点安装。
- 详情里的开关就是「我的智能体」：关掉就从列表里移除，可以撤销。它就是官方版的「启用」，所以新会话的选择器、委托和其它地方都跟着它走。
- 打开设置页时只预检「我的智能体」；别的智能体在你点开时再检测。
- codeg 里还没有某个智能体的设置时（全新安装，或以后版本新增的内置智能体），只启用本机检测到已安装的。codeg 认的「已安装」是它要用的 ACP 适配器或 CLI 已经就位，全新安装时常常一个都没有，列表是空的，从「添加智能体」挑就行。以后新装的智能体不会自动加进来，已有的设置一律不动。
- 从以前的版本升级上来、「我的智能体」里有没安装的，列表顶部会提示一次：「只保留已安装的」或「保持现状」（这个选择按设备记）。
- 新会话的选择器一行末尾多了「+」，点它直接打开「添加智能体」；智能体多到放不下时，它在「更多」菜单的底部。一个智能体都没有时，选择器里的按钮也直接打开「添加智能体」。

</details>

<details>
<summary><strong>手机上长按选中文字</strong> 的细节</summary>
<br/>

- 官方版的整个对话区和输入框都挂着自己的右键菜单，手指长按也会打开它：在回复上按住约 0.7 秒，弹出的是会话菜单（新建会话、导出会话……）；安卓上长按发出的系统事件还被拦下，手机自己的选词也跟着取消。输入框在 HTTPS 下长按，弹出的是它自己的剪切、复制、全选菜单。手机自带的选中手柄和复制菜单出不来，回复和输入框里的文字很难复制。
- 定制版把手指和触控笔的长按交给手机：选中、拖动手柄、复制、粘贴都用手机自带的。鼠标右键照旧打开这两个菜单，带触屏的电脑也一样。
- 官方版选中回复后弹出的「复制文本、引用、提问」气泡贴着选区，手机的菜单也贴着选区，放在上方还是下方由手机决定，网页既读不到也挪不动，两个常常叠在一起。定制版里用手指选中时，这几个按钮和选中的字数出现在输入框下方，暂时顶替文件夹和分支那一行，取消选中后换回来；手机的菜单隔着输入框碰不到这里。「提问」在这一行里直接输入问题。用鼠标选中时仍是浮在选区上方的气泡。
- 输入框菜单里的「快捷消息」在输入框左下角的「+」里也有；翻译要发的消息有自己的按钮。
- iOS 上网页里的普通文字，系统菜单本来就没有「全选」（输入框里才有）；要复制整段回复，用回复下面的复制按钮。

</details>

<details>
<summary><strong>在网页上重启服务器</strong> 的细节</summary>
<br/>

- 官方版部署在服务器上时，网页里没有重启 codeg 的入口：改了需要重启才生效的设置（外观、语言、服务商列表、浏览器代理等），或者服务出了问题，只能登录服务器去重启。在服务器上恢复备份也是这样：恢复要重启后才生效，但它调用的重启只认「有待安装的更新」，每次都提示「服务未能重启，请手动重启」。
- 定制版在「设置 → 系统」的「软件更新」下面加了「重启 codeg」。点「重启」先确认，确认框会写明有几个会话正在运行、会被中断；确认后倒数几秒，等服务回来，页面自动刷新。其他打开着的窗口，状态栏也会显示「正在重启」。
- 重启方式和在线更新一样：Docker 或带守护进程（`--supervise`）运行时，由守护进程重新拉起，间隔是 `CODEG_RESTART_DELAY_MS`；单独运行时，进程原地重新启动（systemd 等看到的还是同一个进程）。普通重启不进在线更新的试运行期，也不会触发自动回滚。在线更新正在下载或安装时不能重启。
- 在服务器上恢复备份后，结果面板里的「立即重启」改用同一个重启，恢复会自动生效。
- 只在服务器版显示：桌面版不显示，用浏览器连到桌面版内置 Web 服务时也不显示；Windows 服务器和在线更新一样暂不支持。

</details>

<details>
<summary><strong>子智能体半路出错能接着做</strong> 的细节</summary>
<br/>

- 你在消息里 @ 一个智能体时，主智能体用 `delegate_to_agent` 把活交给它，它在自己的子会话里干。官方版的 `resume_delegation` 只接得回被取消或因崩溃中断的子任务；子智能体那一轮以错误结束的（断网、额度或限流、登录过期、服务商拒绝请求、token 预算用完等）记为「失败」，主智能体只能再开一个子会话从头做，做到一半的上下文就丢了。
- 定制版把这类失败也当成中断：子任务的结果里写明会话和做了一半的活都还在，问题解决后用 `resume_delegation` 接着做。主智能体照着在原来的子会话里继续，task_id 不变，对话里原来那张子智能体卡片也接着显示进度。
- 用法：网络恢复、额度补上或重新登录之后，对主智能体说「让它接着做」就行。
- 还没建好会话就失败的（比如智能体没能启动）没有可接着做的东西，仍要重新委托。已经做完的子任务要追加新要求，用 `continue_delegation`，见「子智能体在自己的 worktree 里干活」。

</details>

<details>
<summary><strong>设置页分组</strong> 的细节</summary>
<br/>

- 左侧导航按用途分成「基础 / 智能体 / 内容 / 操作 / 连接与维护」5 组，页面和顺序都和官方版一样。
- 外观、常规、系统、版本控制、翻译页把相关的设置收进同一张卡片，卡片上方写组名；只有一个开关或下拉的设置改成一行：名称和说明在左，控件在右。外观页从 12 张卡片变成 3 组，版本控制页的「添加账号」挪到了各自的标题行。
- 每页开头统一是页标题加一行说明；网络代理的开关和其他地方一样是滑动开关；手机上放不下的下拉框和按钮换到说明下面；宽屏浏览器里，表单类页面限制宽度并居中。

</details>

<details>
<summary><strong>子智能体做完会叫醒主智能体</strong> 的细节</summary>
<br/>

- 官方版里主智能体派出子智能体后，只能自己用 `get_delegation_status` 去查：要么阻塞着等，要么隔一会儿查一次。它一旦结束这一轮，子智能体做完了也没人告诉它，要等你再发消息提醒它去查。
- 定制版在子智能体做完（或中途出错停下）时，把结果送回主智能体：
  - 主智能体空闲：等 2 秒（同时做完的几个合成一条），自动开一轮，主智能体看着结果接着做；
  - 主智能体正在跑一轮：Claude Code、Codex、Grok、Kiro、Antigravity 直接插进这一轮，其他智能体等这一轮结束再自动开一轮；
  - 你正好发消息：结果随你的消息一起带过去。
- 对话里会出现一行「子任务结果已交回」，写着哪个子智能体、完成还是失败、用了多久，点开能看每个的结果摘要和「查看会话」；随你的消息带过去的，在你的消息下面显示「附带 N 个子任务结果」。这一行是 codeg 发给主智能体的，不会当成你说的话推到聊天渠道，也不会拿来起会话标题。
- 主智能体已经自己用 `get_delegation_status` 或 `cancel_delegation` 拿到结果的，不再重复送；被主智能体或你手动取消的子任务不送。
- 你点停止只停主智能体这一轮，它名下在跑的子智能体继续干，和官方版一样（官方版 0.50.0 起打断主智能体不再停子智能体）；要停子智能体，用「N 个运行中」里的「停止」或「全部停止」。主智能体被你停下、或那一轮出错结束（限流、断网等）之后，以及连续自动继续了 20 次之后，不再自动开新的一轮：子智能体的结果（包括之前做完还没送到的）等你下一条消息带过去，「N 个运行中」旁边会写明。
- 开关是「设置 → 协作 → 多智能体协同 → 通用」里的「子智能体完成后叫醒主智能体」，默认开启，只对之后启动的会话生效；关掉后和官方版一样，只能由主智能体自己去查。

</details>

<details>
<summary><strong>子智能体在自己的 worktree 里干活</strong> 的细节</summary>
<br/>

- 官方版的子智能体都在主智能体的工作目录里干活，并行派出两个改代码的，会改到同一批文件；用哪个模型只能事先在 @助手 或设置里定好，主智能体没法按任务挑；子智能体做完后要再改点什么，只能开个新会话从头讲一遍。
- 定制版给 `delegate_to_agent` 加了三个参数：
  - `isolation: "worktree"`：子智能体在新建的 git worktree 里干活，分支是 `delegate/<编号>`，从主智能体当前所在的 commit 建出来；主智能体还没提交的改动不在里面，委派的回执里会提醒。worktree 放在「待办任务」设置里的「Worktree 位置」（没设就放在仓库旁边），目录名是 `<仓库名>-delegate-<编号>`。子智能体做完后，结果里写明路径、分支和改了什么，主智能体审查后用 git 合并，或者留给你。只能用在至少有一次提交的 git 仓库里。
  - `model` 和 `config`：只对这一次委派生效的模型和选项（如 `{"reasoning_effort": "high"}`），叠加在 @助手 或设置里的默认值上，没指定的选项照旧。子智能体启动后按它实际提供的选项核对，对不上就不让它开工，并告诉主智能体有哪些可选；它根本没有的选项忽略，回执里会说明。
- 新工具 `continue_delegation`：给已经结束（完成、失败或取消）的子任务追加新要求，在原来的子会话里接着做，之前的上下文、工作目录、模型和选项都沿用，结果同样会送回主智能体。每追加一次算新的一轮，有新的 task_id。和 `resume_delegation` 的分工：半路中断了接着做用 resume，做完了再改用 continue。
- 委派那一行的标题后面多了模型、分支和「第 N 轮」的标签；展开后能看到模型、选项和 worktree 的状态（从哪个 commit 建的、改了几个文件），点「打开」在工作区打开这个 worktree（看改动、提交、合并都在那里），点「删除 worktree」删掉它，可以连分支一起删。
- worktree 不会自动删。删除用过 worktree 的子会话时，确认框里多一项「同时删除它的 worktree」；里面有未提交的改动时默认不勾，并写明有几处。

</details>

<details>
<summary><strong>随时插话</strong> 的细节</summary>
<br/>

- 官方版里，智能体回复时按 Enter 是排队；插话藏在发送按钮旁的小箭头里，只有 Claude Code、Codex 能直接插进去，其他智能体要先在设置里打开「实时反馈」，只能留言等它自己来查。排队的消息只存在当前浏览器里，刷新就没了；点停止后，排着的下一条马上发出去。
- 定制版照 T3 Code 改：
  - 发送按钮：输入框空着时是停止；有内容时图标表示点下去做什么：插话（↱）或排队（列表 +）。按住 ⌘/Ctrl 图标翻成另一种，⌘/Ctrl 点击就做另一种；手机上长按发送按钮选另一种，只对这一条生效。
  - 默认插话；「设置 → 常规 → 标签页与输入」里的「智能体回复时发送消息」可以改成排队，只对这台设备生效。
  - 快捷键（「设置 → 快捷键」里能改）：Enter 按默认方式发；⌘/Ctrl+Enter 用另一种；⌘/Ctrl+Shift+Enter 把最早排队的那条插进去；光标在输入框开头时 Alt+↑ 编辑最近排队的那条。
  - 斜杠命令一律排队；智能体正在压缩上下文时，插话也改成排队。
- 插话怎么送达：Claude Code、Codex、Grok、Kiro（只收文字）和 Antigravity 1.5.0 起直接插进这一轮，做完手上这一步就读到。其他智能体先停下这一轮，再带着你的话在同一个会话里重新开始：被打断的那段回复折叠成「被插话打断的尝试」，被打断的那一步会丢掉；这种停止不会停掉它派出去的子智能体。Grok 不支持原生插话时只能排队（它的取消会连带停掉正在跑的工具）。
- 插进去的消息下面标「插话」，还在路上时标「插话 · 等待读取」，重新载入后标记还在。
- 排队的消息存在服务器上，所有窗口和设备看到同一份，刷新、重启都还在。电脑上显示在对话末尾的虚线气泡里，手机上在输入框上方；每条可以立即发送（有正在进行的一轮就插进去，没有就开新一轮）、编辑、删除、拖动排序。这一轮正常结束后由服务器发下一条，浏览器都关了也照发；发出去的消息会带上还没送到的子任务结果。
- 点停止、这一轮出错结束（限流、断网等）或服务器重启后，队列暂停，输入框上方显示「队列已暂停」和「继续」；点「继续」、在空输入框按 Enter 或发一条新消息都会接着发。点停止时还有插话没送到，会提示「插话没送达」，可以放回输入框。
- 官方版的「实时反馈」（留言）去掉了：设置里没有这个开关，也不再给智能体 `check_user_feedback` 工具。

</details>

<details>
<summary><strong>T3 风格紧凑对话视图</strong> 的细节</summary>
<br/>

- <strong>默认开启，随时可切回</strong>：在「设置 → 外观 → 对话样式」里可在「紧凑（T3 风格）」和「时间线（经典）」之间即时切换，按设备本地保存。
- <strong>过程折叠与实时状态</strong>：回复进行中，「正在工作 Xs」是一行带扫光的计时；做完的每组工具缩成一行摘要（如「读取了 2 个文件，搜索了 1 次」），中间的说明照常显示；正在跑的那一步单独一行、带扫光，点它展开这一组。结束后同一行原地变成「已工作 Xs ›」，下面收起，展开看到的还是那几行摘要，每组再点开看单步（列表最高 18rem、自己滚动、上下渐隐）。展开或收起时，被点的那一行停在原处不跳。未恢复的失败、等待批准的权限请求、提问、计划、运行中的子智能体和生成的图片始终留在折叠外；回复过程中展开过的那轮结束时不自动折。
- <strong>工具调用四档显示</strong>：可在设置或对话标题栏「…」菜单切换「全部显示 / 隐藏成功的 / 全部隐藏 / 禅模式」。
- <strong>改动文件树与差异打开</strong>：答案下方以可折叠目录树展示改动（单子目录链合并、8 个文件以内默认全展开、超过 250 行虚拟化），点击文件直接打开差异面板，新建的 HTML/Markdown/图片可就地预览；展开后的编辑行悬停也能一键在差异面板打开。
- <strong>用户气泡与底栏降噪</strong>：连续用户消息紧贴分组、图片以拼贴放入气泡内、超过 22rem 才折叠，悬停显示时间、复制，以及官方版的原地编辑并重发（支持回退的智能体）。回复底栏（复制、翻译、分叉、建任务、模型、token、时间）悬停才出现，最后一条常驻，实时速度默认隐藏。发送后将你的消息锚定在视口上方 24px，让回复向下生长。
- <strong>新增交互与纯黑主题</strong>：桌面端左边缘提供时间轴缩略图（悬停毛玻璃预览、点击跳转加载历史）；对话区按 ⌘/Ctrl+F（或从标题栏「…」菜单）可搜整个对话的未加载历史并自动展开命中折叠；选中文字「引用」生成输入框引用卡片，发出后点击卡片跳回原文并高亮 2 秒；代码块新增自动换行开关，shell 代码块可一键粘贴到新终端（不自动执行，按回车才跑）；外观主题色新增「墨黑」纯黑预设。

</details>

<details>
<summary><strong>公网远程访问更跟手</strong> 的细节</summary>
<br/>

- 官方版在延迟高、会丢包的公网链路上用起来很卡：流式文字一小块一个 WebSocket 帧，每帧还要等上一帧的确认（Nagle），文字半秒一团地出；丢一个包，系统默认的拥塞控制就把发送速度减半，第一次打开要下载的 1.9 MB 脚本要二十多秒；断线重连会重新拉整份会话快照；截图以 base64 内嵌在会话里，每次打开都整份传；打开一个会话，服务端要把同一份记录解析三遍；离开会话就断开智能体，切回来要重新连接、重新加载。
- 定制版的效果（模拟链路：往返 368 ms、丢包 7%，假智能体；会话有 150 轮、10 张截图）：

  |  | 官方版 | 定制版 |
  | --- | --- | --- |
  | 第一次打开到能输入 | 24.8 秒 | 8–14 秒 |
  | 刷新到能输入 | 2.7 秒 | 1.1–1.2 秒 |
  | 点开长会话到最后一轮可见 | 12.3 秒 | 0.8 秒 |
  | 切回刚看过的会话 | 6.3 秒（全部重新加载） | 0.2 秒 |
  | 回复时文字更新的间隔（中位数 / 95%） | 366 / 460–731 毫秒 | 34–38 / 66–100 毫秒 |

- 连接：服务端的连接关掉 Nagle、改用 BBR 拥塞控制（丢包不再被当成拥堵而减速），内核里压着的待发数据也限得很小，心跳不会排在大块数据后面。WebSocket 加了 `codeg-events.v2` 子协议：流式文字每 100 毫秒合成一帧，大帧压缩后分片发。网页每 5 秒探一次，15 秒没动静才算断线；断了马上重连，只补漏掉的事件；8 秒内恢复不弹提示，断网 3 秒或 8 秒都不用重连。桌面版连远程服务器同样走 v2。
- 打开会话：截图单独按需加载，先给缩略图，看过的不再下载；超过 24 KB 的工具输出先只传开头和结尾，展开时再取全文；第一屏按字节数只取最近几轮；Claude Code 会话解析过的结果服务端会缓存，记录没变就不重新解析。
- 切换会话：离开会话时智能体先停放着不断开，切回来直接接上；在侧栏按下或悬停时就提前取会话内容。停放的智能体会占内存，所以服务端最多留 6 个空闲的，多了就断开最久没用的。
- 启动：带哈希的静态文件长期缓存；刷新直接进工作区；启动要的 20 个请求合成一个，页面脚本还没下载完就发出去。
- 服务端可以用环境变量调整（一般不用改）：

  | 变量 | 默认 | 作用 |
  | --- | --- | --- |
  | `CODEG_WS_COALESCE_MS` | `100` | 流式文字合成一帧的时间窗（毫秒，最大 1000，`0` 不合并） |
  | `CODEG_TCP_CONGESTION` | `bbr` | 网页连接用的拥塞控制算法，内核没有就用系统默认；空或 `off` 不改 |
  | `CODEG_TCP_NOTSENT_LOWAT` | `65536` | 内核里最多压多少还没发出去的字节，`0` 不限 |
  | `CODEG_ACP_MAX_IDLE_CONNECTIONS` | `6` | 最多留几个空闲的停放智能体，`0` 不限（照旧按空闲时间回收） |
  | `CODEG_ACP_IDLE_HOLD_GRACE_SECS` | `90` | 停放的智能体多少秒没人碰才算空闲 |
  | `CODEG_DETAIL_CACHE_ENTRIES` | `6` | 缓存几个解析好的 Claude Code 会话，`0` 不缓存 |

</details>

<details>
<summary><strong>点了就有反应，回复匀速出字</strong> 的细节</summary>
<br/>

- 官方版的按钮都要等服务器回话才变：在往返 368 毫秒的链路上，批准权限后卡片要 0.4 秒才消失，改名、删除要半秒，点停止看不出点没点上；请求在路上丢了就是失败。网络一抖，回复就一阵一阵地跳。
- 定制版：
  - 改名、删除、置顶、改状态，文件夹的颜色、别名、默认智能体，从工作区移除文件夹，批准权限、回答提问、批准计划：本地先改，按下当场生效。服务器拒绝时，如果屏幕上还是你这次的改动，就改回去并提示；选模型或配置没设上时也会改回原来的值。
  - 这些操作的请求遇到网络错误会自动重试，最多两次。发消息、新建会话、插话、排队这类会产生新东西的请求带幂等键，服务器收到重复的只执行一次、回第一次的结果，不会多出一条消息或一个会话。
  - 停止：按下立刻转圈，表示正在停止；只停你按下时的那一轮，如果那一轮已经结束、排队的下一条开始了，不会把它停掉。
  - 切了模式再发消息，模式随消息一起发，少等一个来回。
  - 插话和排队：点下去就清空输入框、进队列；没送到就把内容放回输入框（图片和引用都在）。
  - 新建和分叉会话后不再重新拉整个会话列表。
- 实测（同上链路）：批准权限到卡片消失 0.42 秒 → 5 毫秒；改名 0.49 秒 → 0.06–0.09 秒；删除 0.45 秒 → 0.07–0.2 秒；停止按钮有反应 0.46 秒 → 0.03–0.07 秒。
- 匀速出字：网慢时，回复按最近的到达速度匀速显示，比实际到达晚一点；晚多少按这条链路最近最长的一次停顿自动定（最多 1.5 秒）。网络顺畅时不缓冲，和以前一样。工具卡片、权限请求和这一轮结束出现之前，攒着的字会先全部显示，顺序不乱。同一条链路实测：文字更新的间隔中位数 100 → 34–38 毫秒，95% 190–214 → 66–100 毫秒。「设置 → 外观 → 平滑显示流式文字」可以关，只对这台设备生效。

</details>

<details>
<summary><strong>智能体自己接着干，也显示在运行</strong> 的细节</summary>
<br/>

- 官方版只把 codeg 发出去的那一轮算作运行中。智能体自己开的轮次，例如 Claude Code 的后台命令（`run_in_background`）、Monitor 或后台子智能体跑完、它收到通知接着干，或者 Codex 的 `/goal` 目标还没完成、自己接着下一轮，会话都显示已结束（待复查）：输入框是发送按钮，停不下来，也不会有完成通知。Codex 这一轮的内容还会被丢掉，只剩一个「加载后台活动」按钮。
- 定制版把这些轮次当成正常的一轮：开始时会话变成进行中，标签和侧栏显示在运行，输入框换成停止按钮；结束时和普通一轮一样标成待复查、发完成通知，排队的消息接着发。
- Claude Code：这一轮的内容仍从它的会话记录读出来实时显示，和以前一样。后台任务栏里「Claude Code 正在工作」那一行的停止按钮，和输入框的停止按钮效果相同。需要 claude-agent-acp 0.97.0 及以上（定制版自带 0.113.0）。
- Codex：这一轮的内容直接实时显示。开始和结束看 Codex 报告的线程状态，需要 codex-acp 2.3.0 及以上（定制版自带 2.12.1）。
- 这一轮进行中你发消息时，先结束这一轮，再把消息交给智能体：Claude Code 把它并进正在跑的那一轮里回答，Codex 也接着处理这条消息。
- Grok 在后台工作流结束后自己开的那一轮，官方版已经显示为运行中；定制版让会话状态也跟着变成进行中。

</details>

### 发布方式

|  | 定制版 | 官方版 |
| --- | --- | --- |
| 下载与更新 | 本仓库的 [Releases](https://github.com/keh4l/codeg/releases)，用本 fork 自己的密钥签名 | [spacering-net/codeg](https://github.com/spacering-net/codeg/releases) 的 Releases |
| 版本号 | 上游版本-序号，如 `0.33.0-2` 是基于上游 0.33.0 的第 2 个定制版 | 如 `0.33.0` |
| macOS 公证 | 没有，第一次打开要放行一次（见[安装](#安装)） | 有 |
| Docker 镜像 | 没有 | 有 |

两边的更新互不相通：定制版不会被更新成官方版，官方版也不会被更新成定制版。`keh4l` 分支就是上游的 `main` 加上上面这些改动。

## 安装

### 桌面版

从 [Releases](https://github.com/keh4l/codeg/releases/latest) 下载最新的安装包：

| 系统 | 安装包 |
| --- | --- |
| macOS（Apple 芯片或 Intel） | `.dmg` |
| Windows（x64 或 ARM64） | `-setup.exe` |
| Linux | `.deb`、`.rpm` 或 `.AppImage` |

它和官方版是同一个应用：装上后会替换官方版，原有的对话和设置都会保留。

> [!NOTE]
> macOS 第一次打开时如果提示「已损坏」或「无法打开」，执行一次下面的命令，或者在「系统设置 → 隐私与安全性」里允许打开：
>
> ```bash
> xattr -cr /Applications/codeg.app
> ```

### 服务端

Linux 或 macOS：

```bash
curl -fsSL https://raw.githubusercontent.com/keh4l/codeg/keh4l/install.sh | bash
CODEG_STATIC_DIR=/usr/local/share/codeg/web codeg-server
```

Windows（PowerShell）：

```powershell
irm https://raw.githubusercontent.com/keh4l/codeg/keh4l/install.ps1 | iex
$env:CODEG_STATIC_DIR="$env:LOCALAPPDATA\codeg\web"; codeg-server
```

两者都从本仓库的 Releases 安装，服务端内置的更新也走这里。

### 换回官方版

> [!WARNING]
> 先备份 Codeg 的数据。定制版有几个官方版没有的数据库迁移（例如翻译功能用的表），官方版可能无法用同一份数据启动。
